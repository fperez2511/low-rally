# Low Rally

A mobile-first, low-poly arcade rally game that runs as an installable PWA.
TypeScript + Vite + Three.js, no physics engine, no external assets: the car, scenery and icons are all generated in code.

![palette](public/icon.svg)

## Run it

```bash
npm install
npm run dev
```

Open the printed `http://localhost:5173`. Click / tap to start, then drive one lap. Your ten fastest laps are kept on the device as a leaderboard (open it from the start screen or the finish banner).

| Input | Steer | Throttle | Brake / reverse | Restart |
| --- | --- | --- | --- | --- |
| Keyboard | ← → or A D | ↑ or W | ↓, S or Space | R or the button |
| Touch | hold left / right half of the screen | automatic | on-screen **Brake** button | the button |

Braking while turning at speed unloads the rear tyres and kicks the car into a drift; lift off or counter-steer to catch it. Grass is slower and has less grip.

## Test on your phone (local network)

The dev server already listens on all interfaces (`server.host: true`).

1. Put the phone on the same Wi-Fi as your computer.
2. Run `npm run dev` and note the `Network:` URL it prints (e.g. `http://192.168.1.20:5173`).
3. Open that URL in Safari / Chrome on the phone. If it doesn't load, check the computer's firewall allows the port.

Notes:

- The game itself works over plain HTTP on the LAN. **Service workers (offline mode / install) only work on `https://` or `localhost`**, so the PWA bits can't be tested from a LAN IP. To test them on a phone use an HTTPS tunnel, e.g. `npm run build && npm run preview` in one terminal and `npx cloudflared tunnel --url http://localhost:4173` (or ngrok) in another, then open the `https://` URL it gives you.
- iOS Safari only starts audio after a tap, which is what the start screen is for.
- Landscape is recommended; portrait works (the camera widens its FOV).

## Build and deploy as a PWA

```bash
npm run build      # type-checks, then writes dist/ (app + manifest + service worker)
npm run preview    # serve dist/ locally to check the production build
```

`dist/` is a static site: upload it to any HTTPS static host (Netlify, Cloudflare Pages, Vercel, GitHub Pages, S3 + CDN...).

- Assets use relative paths, so it works from a sub-path. To be explicit, set `BASE_PATH`, e.g. `BASE_PATH=/low-rally/ npm run build` for `https://<user>.github.io/low-rally/`.
- `vite-plugin-pwa` generates `manifest.webmanifest` and a Workbox service worker that precaches the whole app, so after the first visit it runs offline and can be installed ("Add to Home Screen" on iOS, install button in Chrome/Edge/Android). Updates are picked up automatically on the next load.
- Icons live in `public/` and are generated by `npm run icons` (`scripts/make-icons.mjs`, dependency-free). Edit the polygons there if you want a different icon.

## Project layout

```
src/
  main.ts          bootstrap, renderer/scene, fixed-timestep game loop
  config.ts        the 6-colour palette and every tuning constant
  stage.ts         one-lap stage timer; submits finished laps to the leaderboard
  leaderboard/     top-10 model (ranking, validation, legacy import) + storage strategy (localStorage / memory)
  audio.ts         AudioContext unlock + minimal engine hum
  input/           InputState interface; keyboard + touch sources; merge
  world/           track (spline + spatial hash), terrain (noise heightfield),
                   chunk manager (pooled terrain + road meshes), props, start line
  car/             controller (the handling model), model (primitives), camera rig
  ui/              HUD, start screen, leaderboard panel, palette -> CSS variables
```

### How it works (the non-obvious parts)

- **One heightfield.** `Terrain.heightAt(x, z)` is seeded value-noise hills, blended onto the road's own elevation profile within 40 m of the road. The terrain meshes, the car's four wheel samples, the camera floor and the props all call it, so the car sits exactly on what you see.
- **Track.** A closed Catmull-Rom loop through seeded control points (star-shaped, so it can't cross itself), resampled every 2 m into typed arrays, plus a spatial hash so "nearest road point" is a handful of segment tests. That one query gives the road/off-road surface, the terrain blend and prop clearance.
- **Chunks.** 80 m chunks in a 5×5 square around the car live in a fixed pool; geometry buffers are allocated once and rewritten in place as you drive, spread across frames. Each chunk owns its terrain mesh, the road quads for the centreline samples inside it, and deterministic prop placements (seeded by chunk coordinates, so scenery never reshuffles).
- **Props.** All trees are one `InstancedMesh`, all rocks another; their matrix buffers are refilled from the live chunks only when the chunk set changes.
- **Car handling** (`src/car/controller.ts`, commented in place):
  - *Steering* is a kinematic bicycle model: `yawRate = v / wheelbase · tan(δ)`, with the wheel angle δ shrinking as `1 / (1 + (v / 10)²)` so the car stays controllable at speed.
  - *Grip*: lateral velocity is removed by the tyres up to a cap (`gripAccel`). The cap fades with slip angle (the grip curve), so once the car is sideways it keeps sliding until you unwind the wheel; braking while turning cuts rear grip to start a drift; grass scales grip, engine power and drag.
  - *Longitudinal*: engine pull tapers to zero at max speed, plus rolling + quadratic drag; brake slows, then reverses once stopped.
- **Leaderboard.** `Leaderboard` is a DOM-free model over a `LeaderboardStore` (`localStorage` if usable, otherwise in-memory for the session). Times are stored as `{ v: 1, entries: [{ time, date }] }` under `lowrally.leaderboard.v1`, written once per finished stage after re-reading storage so other tabs' runs are merged. On first load the old single best time (`lowrally.best.v1`) is imported once as an undated entry; the old key is left untouched. Bad or corrupt stored data is dropped entry by entry. Design notes are in `specs/001-persist-leaderboard/`.
- **Loop.** Simulation steps at a fixed 60 Hz; rendering interpolates between the last two sim states, so it's smooth at 60/90/120 Hz displays. Pixel ratio is capped at `min(devicePixelRatio, 2)`, MSAA is skipped on ≥2× screens, there are no real-time shadows (blob shadow instead), and the game loop allocates nothing (HUD DOM writes are throttled to 10 Hz and only on change).

## Scope

This is an MVP. The stage is a single lap of a seeded loop; the line at the start is also the finish. The dev build exposes `window.__game` for poking at state from the console (stripped from production builds).

## Next steps (deliberately not built)

- AI opponents / ghost car of your best run
- Multiplayer
- Menus: stage select, car select, settings, pause
- Checkpoints / wrong-way detection (the timer only follows progress along the road, so a determined shortcut across a hairpin could cut time)
- Multiple procedural stages, point-to-point stages, seed picker
- Props collisions and car damage; jumps / airtime
- Surface types (gravel, snow, tarmac) with different tuning, dust and skid-mark particles
- Real audio: engine samples, tyre squeal, co-driver
- Gamepad and tilt-to-steer input sources (they would just implement `InputSource`)
- Haptics, a proper loading screen, offline-update toast
